# 项目历史：仍然有效的结论与规则

本文件只存**今天仍然成立**、或**解释现行做法为什么这样**的东西。逐笔提交叙事、旧 SHA 对照表与已完成的
操作步骤都不在这里；活文档分别在 `TOOLING.md`（工具与流程）、`REPO_SCOPE.md`（边界）、
`docs/DIALECT_EXTENSION_RECORD.md`（语种调研）。

## 1. 生成物与 cpp-pinyin 的漂移追溯——结论

`tools/check_drift.ps1` 至今按这套口径比对两仓，所以"结论怎么变的"值得留：

- **普通话 `word.txt`**：23 个新增行 + 5 个读音漂移。早期判定为"漂移即缺陷"，后来收敛为：只比
  **两仓共有的键**，新增/删除分别计数而不是直接判红——否则每次上游扩词都会被报成不一致。
- **粤语**：长期只有 **1 行**差异（13 个汉字的位置），根因是句内 `U+0020` 被静默吞掉（cpp 侧 `isSpace`
  只匹配半角空格，其它空白保留占位）。cpp 侧的判断在 `src/G2pglobal.cpp` 的 `isSpace`（只认 U+0020），调用处的取舍写在 `src/EngineImpl.cpp` 的注释里。
- **现行状态**：两方言 8 张表与产地仓 **SHA-256 全等**，`check_drift` 报 0 漂移。

**教训（仍然有效）**：漂移检查必须**先声明比什么**（共有键？全体键？含新增/删除？），否则同一个事实会有
多种合法答案，而每种答案看起来都像结论。

## 2. 压缩与清理留下的四条硬规则

1. **不重编号历史**：编号是历史坐标，重编号等于伪造历史；要长期引用就新建一个已立册的记号。
2. **备份 ref 不推远端**：备份的作用是本地回滚，推上去就把旧历史变成了公开事实。
3. **压缩的正确性只认 `git diff` 为空**，不认"树看起来对"。
4. **操作记录在动作完成后就该删除**：它解释的是"当时为什么那么做"，一旦动作不可逆地完成，留档的唯一
   作用就是让读者以为还有待办。
